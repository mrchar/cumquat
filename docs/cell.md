# 单元格竞选

> 机制已随 Table 落地：内建 Cell 集与 `registerCell` 由 @cumquat/components 导出，`TableColumn` 支持 `type` / `format` / `cell` / `bias`，Table 支持 `cells` 局部渲染器。用法速览见 [Table 表格](/components/table)。

## 动机

列表页里「这一格显示什么」是一个被低估的问题。字段元数据已经描述了两层事实：

- **type**：数据的保存格式（string / number / boolean / datetime / enum…）
- **format**：内容的格式（email / uri / uuid / int64 / date-time…）

同一 type 的列，显示方式可能完全不同：`string + email` 应渲染为邮箱链接，
`string + uri` 应渲染为外链，`datetime` 应本地化格式化，`enum` 应显示选项
label 而非原始值。type 与 format 对客户端都有意义，都应导出，显示推断同时
消费两者。

传统做法各有困境：

- 组件内部硬编码 if/else：不可扩展，每支持一种格式就加深一处分支
- 宿主逐列手写插槽：列一多元数据驱动就失去意义

目标：**Table 直接绑定 columns 定义，单元格显示由列定义自动推断**；宿主与
第三方可以插入新的显示实现，而无需修改组件内部。

## 设计原则

1. **自包含的单元格渲染器**：每个 Cell 只声明「我擅长什么、我怎么渲染」，不感知其他 Cell，不依赖渲染顺序
2. **自我评价代替注册表匹配**：Cell 对**整个列定义**返回一个**适配度分数**，由**竞选代理**裁决，声明式且可组合——「比较擅长」与「最擅长」是梯度而非布尔。评价输入不限于 type / format，列的任何字段（key、title、options、filters、宿主附加字段…）都可参与
3. **按列竞选，不按单元格竞选**：一列裁决一次、全列统一渲染策略；单元格值的异常由选中 Cell 自行降级（如 enum 值不在 options 中显示原值）。裁决结果随列定义缓存，开销为 列数 × Cell 数
4. **兜底恒在**：所有 Cell 弃权时回落默认文本渲染，机制对「随手写 columns」的用户零打扰
5. **视觉中立**：Cell 产出语义 class（如 `cumquat-cell--enum`），样式完全交给主题机制

## 机制

### 核心概念

- **Cell（单元格渲染器）**：`列定义 + 值 → 展示内容` 的实现。展示内容可以是格式化文本，也可以是结构化呈现（链接、徽标、标签）。
- **适配度分数（fitness）**：Cell 对**完整列定义**的自我评价，纯函数、无副作用。输入是列定义整体——key、title、type、format、options、filters、width…以及宿主附加的自定义字段；type / format 只是其中常用字段，不是评分的全部。约定：正数越大越适配，`0` 表示弃权不参与。分数只在一次竞选中相互比较，没有跨列的绝对意义。
- **竞选代理**：无状态裁决者。对每一列收集全部注册 Cell 的分数，取最高者；**同分时先注册者优先**（稳定、可预期）；无正分则回落默认文本 Cell。

### 运行流程（每列一次）

1. 代理取出该列的完整定义（含宿主附加字段）
2. 遍历注册表，各 Cell 依据列定义自我评价，返回适配度分数
3. 应用列上的外部加成（`bias`，正负均可）
4. 取最高分（同分先注册者优先）；无正分回落默认文本
5. 被选中的 Cell 渲染该列全部单元格，自行处理空值与越界值
6. 列存在显式配置或插槽时跳过竞选（见下）

### 优先级链路

```
插槽 > 显式指定 cell > 竞选推断 > 默认文本
```

- **插槽**（`#cell-{key}`）：完全交给宿主，操作列等交互内容走这里，优先级最高
- **显式指定 cell**：宿主在列定义上按名称指定某个 Cell（如 `cell: 'tag'`），指定即生效，不走分数
- **竞选推断**：默认路径，零配置
- **默认文本**：兜底，原样显示

### 外部调整

竞选之外提供三层外部调整，从轻到重：

| 层级 | 位置          | 语义                                                                                                             |
| ---- | ------------- | ---------------------------------------------------------------------------------------------------------------- |
| 加成 | 列定义 `bias` | `bias?: Record<string, number>`，对指定 Cell 加减分，正负均可；代理在裁决前应用，可翻转竞选结果而无需注册新 Cell |
| 指定 | 列定义 `cell` | 按名称显式指定 Cell，跳过竞选（见优先级链路）                                                                    |
| 覆盖 | 注册表        | 同名重注册替换既有实现（含内建），全局调整某一类内容的显示                                                       |

- 加成示例：某状态列想用标签展示，`bias: { tag: +30 }` 即可让 tag 胜过 enum，无需重写评分
- 覆盖示例：宿主重注册 `email`，全部邮箱列统一换用自家链接组件
- 三层调整都不改变优先级链路，只改变「竞选推断」这一层的结果

## 内建 Cell 与评分约定

| Cell     | 得分依据                                | 显示效果                |
| -------- | --------------------------------------- | ----------------------- |
| text     | 恒为 `1`（兜底）                        | 原始值文本              |
| number   | `type: number` → `80`                   | 数值格式化              |
| boolean  | `type: boolean` → `90`                  | 是 / 否 徽标            |
| enum     | `type: enum` → `100`                    | options 中的 label 标签 |
| date     | `type: date` → `90`                     | 日期格式化              |
| datetime | `type: datetime` → `95`                 | 本地化日期时间          |
| email    | `format: email` → `95`                  | 邮箱链接                |
| link     | `format: uri` → `95`                    | 外部链接                |
| tag      | `format: tag` / `format: status` → `85` | 语义标签                |

- 表中得分依据仅是内建 Cell 的实现选择（恰好使用 type / format）；契约本身允许 Cell 依据列定义的任何字段评价。评分不看单元格值，值只进入渲染阶段
- `format` 得分普遍高于同 source 的 `type` 得分：内容格式比保存格式更具体，更具体者优先
- 内建集刻意保持克制；更多格式（`uuid`、`int64`、`binary`…）留给宿主按同一契约扩展

## 扩展

宿主按同一契约注册自定义 Cell，参与全局竞选或局部竞选：

```ts
/** Cell 契约（示意） */
interface CellRenderer {
  /** 注册名：显式指定的目标 */
  name: string;
  /** 自我评价：完整列定义 → 适配度分数，0 表示弃权 */
  fitness: (column: ColumnMeta) => number;
  /** 渲染：值 → 展示内容；需自行处理空值与越界值 */
  render: (value: unknown, column: ColumnMeta) => VNodeChild;
}

// 注册「进度条」Cell：对 format: percent 给出高分，其余弃权
registerCell({
  name: 'progress',
  fitness: (column) => (column.format === 'percent' ? 95 : 0),
  render: (value) => h(Progress, { value: Number(value) }),
});
```

- 宿主已有请求列只需在字段元数据上补 `format: 'percent'`，列表即自动换用进度条渲染——**扩展点在 Cell，不在 Table**
- 全局注册与 Table 局部追加都会进入竞选；显式指定的名称在局部注册命中时以局部为准
- `ColumnMeta` 是完整列定义：宿主在 columns 上附加的自定义字段原样进入评价输入，Cell 可依据自有字段评分（如某列带 `cellMeta: { progress: true }` 时给出高分）

## 与既有机制的关系

- **列元数据**：columns 的 `type` / `format` 是可选提示字段——来自资源池投影时自动携带；宿主手写 columns 时缺省全部走兜底文本，机制无害
- **插槽与操作列**：`#cell-{key}` 与 `expanded` 行为不变，竞选只接管「无插槽、未显式指定」的普通数据列
- **主题**：Cell 产出的语义 class 与 CSS 变量走既有主题机制，basic 定义基础样式，其他主题按需覆盖
- **排序 / 筛选 / 分页**：与展示无关，机制不触碰
- **字段竞选**：同一套机制形态在表单侧的对应物——一个管展示（Cell），一个管录入（Field）；资源池的 `columns` 与 `properties` 投影分别对接两者，详见[字段竞选](/field)

## 非目标

- **不做单元格级竞选**：按列裁决保证同列渲染一致，且性能可预期
- **不做异步 Cell**：单元格渲染是同步的，数据获取属于 fetch / subscribe 的职责
- **不处理编辑态**：编辑是表单控件的职责
- **不做单元格级别的值转换配置**：值 → 展示的逻辑收敛在 Cell 内部，避免列上再长出一套转换 DSL

## 落地清单

- **字段元数据**：`ResourceField` 导出 `format`（原样透传文档声明的格式值）；`ResourceColumn` 投影携带 `type` / `format`
- **组件**：内建 Cell 集与 `registerCell` 由 @cumquat/components 导出；`TableColumn` 增加可选 `type` / `format` / `options` / `cell` / `bias` 字段（完全向后兼容），Table 增加 `cells` 局部渲染器属性，列渲染管线已接入竞选
- **文档**：本页注册进导航，[Table 文档](/components/table)含用法演示，资源池文档交叉引用
- **测试**：评分裁决与同分稳定性、bias 加成与注册覆盖、优先级链路（插槽 / 显式 / 竞选 / 兜底）、内建 Cell 覆盖矩阵、宿主注册扩展均有用例覆盖
